# 临时脚本

文档记录一次性 Python 操作。调用的函数、模块和枚举以源码为准。未实现的函数不写入。

片段在已有事件循环的 shell 里执行，顶层可以直接 `await`。

## 1. 确定输出路径

用户给出路径则用该路径。未给出则提问，得到路径再写。

要我们起文件名时，用 `<主题>-<事项>.md`。

已有 frontmatter 时保持原样。新建且需要任务 frontmatter 时，用 [templates.md](templates.md) 的 Frontmatter 块。

完成：目标路径已确定。文件名由我们起时，符合 `<主题>-<事项>.md`。

## 2. 采集事实

按文档会写到的部分逐项读取。读不到的标成「无」。

| 事实                             | 来源                                |
| -------------------------------- | ----------------------------------- |
| 要调用的函数、模块路径、参数     | 源码                                |
| 枚举名与值                       | `model_enums`（脚本要按类型分支时） |
| 执行顺序，以及后一步用到的变量名 | 调用关系                            |
| 步与步之间的等待或人工条件       | 用户说明                            |
| 本次使用的 id                    | 用户给出的值                        |

完成：每个将写入的调用都能在源码里对上；用户没给的 id 已标成「空」。

## 3. 定结构

```
├─ 同一次操作拆成多步，后步使用前步的变量
│    → 一个 ### <操作名> 下按顺序放多个 python 块
│    → 步名写在代码块的 title
│    → 可跳过的步，title 末尾加 (Optional)，块内重新取出后面要用的对象
├─ 同一目的、不同范围
│    → ## 脚本 下每个范围一个 ###，每节单独能执行
└─ 步与步之间要等待或确认
     → 一两句正文，放在相邻代码块之间
```

块的写法见 [templates.md](templates.md)。

完成：属于哪一支已经定下。

## 4. 写入

把定下的块写入目标路径。

- 代码块语言是 `python`
- 用户给了的 id 写进该块的调用，或写在该块顶部的常量里；没给的用空字符串
- 只保留这段脚本用到的 import
- 不同范围的节不共用变量

完成：文件已写入；结构与第 3 步一致；调用与第 2 步的事实一致。

## 5. 自检

- [ ] 每个函数调用的模块路径、参数与源码一致
- [ ] 同一节里后一块用到的名字，在前面的块里已经出现
- [ ] 分范围的每一节能单独执行
- [ ] 可跳过的步在 title 里标了 `(Optional)`
- [ ] 等待和人工条件写在代码块之间
- [ ] 没有编造的 id

完成：每一项为通过，或不适用并注明原因。
